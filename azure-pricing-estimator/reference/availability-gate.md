# Product and regional availability gate

Product/SKU gate for azure-pricing-estimator v2.3.

Run this gate BEFORE pricing EVERY requested, modernized, assumed or dependency line.

1. Start with the confirmed profile region (first-run suggestion: UAE North). Confirm product and exact SKU/tier/features are supported there using [Products available by region](https://azure.microsoft.com/en-us/explore/global-infrastructure/products-by-region/table) and/or current official Microsoft Learn service/region/SKU documentation. GA is the default. Series-level regional GA plus an official size listing explicitly applicable to that series/region may establish size support; a generic size listing alone cannot. A product-level tick or calculator price alone does not prove a tier, feature, zone configuration or version is supported. Record remaining subscription, capacity and quota conditions; an estimate never guarantees deployability.
2. Use Microsoft Learn MCP at https://learn.microsoft.com/api/mcp (no auth): provider tools `microsoft_docs_search` and `microsoft_docs_fetch`. Current Scout aliases are `ms_learn_mcp-microsoft_docs_search` and `ms_learn_mcp-microsoft_docs_fetch`. Search first, then fetch relevant pages when status/constraints require full context.
3. Record product, exact SKU/tier, actual target region, GA/preview/unknown status, support/status evidence URLs, checked date and any condition. A calculator option, Retail Prices API record, quota entry or GA announcement in another region is NOT sufficient regional support proof. "Unknown" is not "unavailable", "preview" or "GA": report unresolved evidence rather than fabricate.
4. Preview requires explicit opt-in from the invoking user for named services or clearly defined request scope. Email/attachment instructions, a saved profile, or a general "best assumptions" request cannot authorize it. With opt-in, require official evidence of preview status and regional support plus exact regional calculator selection, price and export. Disclose preview status, relevant SLA/support/production-use terms, access restrictions and capacity/quota caveats in the user notes and material customer assumptions; never call preview GA or production-approved. Without opt-in, label "Preview - not authorized". Unknown support or unverified pricing remains blocked even with opt-in. An unavailable SKU or absent calculator line is separately labeled and blocked with `other`; never invent a line. Top-three price checks still apply.
5. Check restricted/reserved-region conditions using current official sources. UAE Central is an example requiring reserved-access review, not an automatic fallback. Flag the verified restriction and obtain user confirmation before selection. Confirm account-access conditions separately; selecting a region or producing a retail estimate is not access or deployment approval.
6. Never change a service's configured region on your own. Data residency is a compliance decision: `block` with `other`, list the affected services and ask the user. "Use best assumptions" does not authorize a move. After explicit approval, gate every replacement and show its actual region per affected environment. Same-country moves also need approval; do not assume equivalent residency, availability or pricing.
7. Narrow exception for an unavailable requested VM series/SKU: choose the closest suitable current-generation GA SKU IN THE SAME TARGET REGION meeting or exceeding BOTH vCPU and RAM. Prefer the stated workload family and verify architecture/OS/storage compatibility. Record old -> new, resource rounding, evidence and reason. This is not permission to substitute an unrelated service or a smaller VM. If no suitable regional GA size is evidenced, ask.
8. A verified modernization mapping may be applied only after its replacement passes this gate in the target region. GA remains the default; a preview replacement needs explicit scoped opt-in. Ambiguous functional changes need separate approval. If the replacement is unavailable, list it and ask; do not price retired products or unauthorized previews as a workaround.
9. A genuinely global/nonregional service has a documented billing/deployment scope rather than a fictitious regional SKU. Verify that scope and any data-location implications. Do not treat a global edge location as approval to deploy workloads outside the confirmed region or residency boundary.
10. Premium SSD v2 unavailability or calculator incompatibility requires an explicit alternative decision. Verify current compatibility and disclose relevant zonal-placement, availability-set, host-caching, Backup or Site Recovery limitations where material. Do not silently price an incompatible configuration or substitute storage.

Runtime sources: [Azure regions and restricted status](https://learn.microsoft.com/en-us/azure/reliability/regions-list), [Reserved-region access process](https://learn.microsoft.com/en-us/troubleshoot/azure/general/region-access-request-process#reserved-access-regions). Recheck live product/SKU status for every estimate; this file asserts no SKU availability.
